# Documents

PullMD converts documents and uploaded files to Markdown. The MarkItDown sidecar, which the default compose file runs, handles PDF, Word (DOCX), PowerPoint (PPTX), Excel (XLSX, XLS), EPUB, and ZIP (converts each file inside), plus documents fetched by URL, including CSV, JSON and XML. PullMD reads e-mail, OpenDocument, RTF, and the other [upload formats below](#upload-formats-pullmd-reads-itself) without the sidecar.

## Convert a document by URL

To convert a document by URL, pass a direct link to the file, as you do for a web page:

```bash
curl "http://localhost:3000/api?url=https://example.com/report.pdf"
```

PullMD recognizes the document from its content type, or from the file extension when the server sends no content type or `application/octet-stream`, and sends it to MarkItDown. The result is cached and gets a share link like any other conversion. The title is the host name (`# example.com`) unless the document has one.

## Upload a file

To convert a local file, send its raw bytes to [`POST /api/file`](/reference/api/convert/convert-a-file) with `Content-Type` set to the file's type. PullMD doesn't decode multipart forms, so send the file itself as the body.

```bash
curl -X POST "http://localhost:3000/api/file" \
  -H "Content-Type: application/pdf" \
  -H "X-Filename: report.pdf" \
  --data-binary @report.pdf
```

```markdown
# report.pdf

Release checklist

Run through these steps before every release so nothing ships half-finished.
…
```

- **Maximum size:** 25 MB.
- **`X-Filename`:** the file name, URI-encoded. PullMD uses it for the suggested download name, and as the title when the document has none. `?filename=` also works, but the header keeps the name out of proxy access logs.
- **`Content-Type`:** the file's type. PullMD uses it, together with the file name, to pick the reader.
- **`lang`:** `lang=en` sets English labels in e-mail, calendar, contact, OpenDocument, notebook and feed output. The default is German.
- **Privacy:** PullMD never stores the uploaded file. The conversion creates no history entry or share link, and the stats record it as `local-file`, not the file name. With `async=1`, PullMD holds the converted result in memory for a limited time; see [below](#leave-the-app-during-a-long-conversion).

In the web app, drag a file onto the page or use the file picker.

## Leave the app during a long conversion

Audio transcription, OCR and image descriptions can take longer than a browser keeps a request open. With `async=1`, PullMD takes the upload, answers at once with a job id, and converts the file in the background. You collect the result with a second request, so the connection doesn't have to stay open while the conversion runs.

In the web app, a document upload uses this by default. After the upload finishes, you can switch to another app and come back: the page checks the job every 2 seconds while it is open and shows the result when the job is done. Keep the app open while the file uploads. If the upload is cut off, the app shows `Upload interrupted. Keep the app open during the upload and try again.`

### Use the async API in a script

<Steps>
  <Step title="Upload with async=1">
    ```bash
    curl -X POST "http://localhost:3000/api/file?async=1" \
      -H "Content-Type: audio/mp4" \
      -H "X-Filename: memo.m4a" \
      --data-binary @memo.m4a
    ```

    ```json
    { "jobId": "2f2f4a7b37f071b7e3137d42eb9dbec3", "status": "pending" }
    ```
  </Step>
  <Step title="Poll until the job is done">
    ```bash
    curl "http://localhost:3000/api/file/jobs/2f2f4a7b37f071b7e3137d42eb9dbec3"
    ```

    The answer is `{ "status": "pending" }` while the file converts. When it is `done`, the body holds `markdown`, `metadata`, `source`, `shareId` (always `null`) and `suggestedFilename`. When it is `error`, the body holds `error` and `httpStatus`, the status the same conversion would have returned without `async`: `422` or `502`.
  </Step>
  <Step title="Delete the job">
    ```bash
    curl -X DELETE "http://localhost:3000/api/file/jobs/2f2f4a7b37f071b7e3137d42eb9dbec3"
    ```

    The answer is `204`. Fetching a result doesn't remove it, so you can fetch it again until you delete it.
  </Step>
</Steps>

- **Both answers:** the server can't always queue a job. When async jobs are off, 100 jobs are already held, your user or address already holds 3, or half of the result memory (32 MB by default) is in use, it converts the file in the same request and answers `200` with the normal result, as it does without `async`. A script has to handle `202` and `200`.
- **Deleting a running job:** `DELETE` on a job that is still converting answers `204`, and the job is gone for `GET` and `DELETE` from then on. It still counts toward the 3 jobs of your user or address until its conversion ends, and its result is discarded.
- **Result format:** an async result is always JSON. `format` is ignored for async jobs, and `frontmatter`, `pdf` and `lang` work as they do for a synchronous upload.
- **Retention:** a finished result stays in memory until you delete it or 60 minutes pass (`PULLMD_FILE_JOB_TTL_MINUTES`), except that when your share of the result memory is used up, your older finished results are dropped first, oldest first, to make room for a new one. A result is never written to disk, and a restart loses it.
- **Size limit:** all held results together may use 64 MB of memory (`PULLMD_FILE_JOB_MAX_MB`), and the results of one user or address at most a quarter of that (16 MB by default). Results of other users or addresses are never dropped to make room. A result that doesn't fit becomes an `error` with `httpStatus` `507`: `Result too large to hold for pickup, upload again. / Ergebnis zu groß zum Bereithalten, bitte erneut hochladen.` Raise `PULLMD_FILE_JOB_MAX_MB`, or upload without `async`.
- **Stuck jobs:** a job that is still pending after 15 minutes becomes an `error` with `httpStatus` `504`: `Conversion timed out. / Konvertierung abgebrochen (Zeitlimit).`
- **Access:** with sign-in enabled, send the same API key on all three requests. Only the account that started a job can fetch or delete it, and any other account gets `404`. Without sign-in, the job id is the only credential, so treat it like a share link.
- **Unknown ids:** an unknown, expired, deleted or foreign id gives `404` with `Job not found or expired. / Auftrag nicht gefunden oder abgelaufen.` More than 120 unknown ids a minute from one address give `429` with a `Retry-After` header.

See [`GET /api/file/jobs/{id}`](/reference/api/convert/get-an-async-file-result) and [`DELETE /api/file/jobs/{id}`](/reference/api/convert/delete-an-async-file-result) in the API reference. Set the retention and the memory limit in [Configuration](/reference/configuration#async-file-conversions).

## Upload formats PullMD reads itself

These uploaded formats work without the MarkItDown sidecar. PullMD picks the reader from the file name, so set `X-Filename`. The `X-Source` header names the reader that ran.

| Format | Result | `X-Source` |
| --- | --- | --- |
| E-mail: `.eml`, `.msg` | The subject as title, then From, To, Cc, Date and the message text. Attachments are listed by name. | `email` |
| Saved pages: `.mhtml`, `.mht` | Extracted like [`POST /api/html`](/guides/local-html). The original URL in the file appears as the frontmatter `url`, and site recipes apply. | The extractor that ran |
| Text: `.txt`, `.md`, `.markdown`, `.rst`, `.adoc`, `.asciidoc`, `.org`, `.textile`, `.wiki`, `.nfo` | The text, with a title line added when it has none. A note's own YAML frontmatter becomes a fenced `yaml` block. | `text` or `markdown` |
| Subtitles: `.srt`, `.vtt` | Readable paragraphs without cue numbers, timestamps or styling. | `subtitles` |
| OpenDocument: `.odt`, `.ods`, `.odp` | Headings, links, lists, tables and footnotes. Spreadsheets give one table per sheet, and presentations give one section per slide with speaker notes. | `opendocument` |
| RTF: `.rtf` | Paragraphs, headings, links, lists and tables. | `rtf` |
| Calendar: `.ics`, `.ical` | One section per event with start, end, location, organizer, attendees, recurrence and description. Times use the server's time zone. | `calendar` |
| Contacts: `.vcf`, `.vcard` | One section per card. | `contact` |
| Data: `.csv`, `.tsv`, `.json`, `.jsonl`, `.xml` | CSV and TSV as a Markdown table, JSON and XML in a code block. | `data` |
| Feeds: `.rss`, `.atom`, or `.xml` with an RSS or Atom root | The feed title, then one section per entry. | `feed` |
| Notebooks: `.ipynb` | Markdown cells as they are, code cells and text outputs in code blocks. | `notebook` |
| Code, config and logs: `.py`, `.js`, `.yaml`, `.log`, `Dockerfile` and more | The file name as title and the content in a code block tagged with the language. | `code` |

With `frontmatter=true`, e-mail results carry `title`, `author`, `published` and `source: email`.

A file that doesn't match its format, such as an `.eml` file without mail headers, returns `422`.

## Tables in PDFs: use OCR

MarkItDown reads the text layer of a PDF, which works for prose but loses the structure of complex tables. To keep tables intact, turn on the OCR tier, which sends the PDF to an OCR provider that returns Markdown.

<Steps>
  <Step title="Add a provider key">
    ```bash
    PULLMD_PDF_OCR_API_KEY=your-key
    ```

    The default provider is Mistral OCR (`mistral-ocr-latest`, about $0.002 per page). To use another endpoint that speaks the Mistral OCR API (`POST /ocr`), set `PULLMD_PDF_OCR_BASE_URL` and `PULLMD_PDF_OCR_MODEL`.
  </Step>
  <Step title="Ask for OCR per request">
    ```bash
    curl "http://localhost:3000/api?url=https://example.com/report.pdf&pdf=ocr"
    ```

    `pdf=ocr` also works on `POST /api/file` and `/api/stream`. On the MCP server, pass `pdf_ocr: true`. For a site whose PDFs always need it, set `fetch.pdf: ocr` in a [site recipe](/guides/site-recipes).
  </Step>
</Steps>

When OCR runs, `X-Source` is `pdf-ocr` and the frontmatter gains `pdf_pages`. If the provider fails, no key is set, or the PDF is over 50 MB, PullMD uses the standard conversion instead; the request doesn't fail.

<Note title="OCR key">
  OCR doesn't use the shared `PULLMD_LLM_API_KEY`, because OCR providers are usually different from chat-model providers. Set `PULLMD_PDF_OCR_API_KEY` explicitly.
</Note>

OCR requests count against the hourly provider budget, `PULLMD_LLM_RATE_LIMIT` (default 30 per user or address, shared with image captions and audio transcripts). Over budget, PullMD uses the standard conversion and doesn't cache that result.

A local engine such as [Docling](https://github.com/DS4SD/docling) needs an adapter that translates the Mistral OCR request. The OCR tier handles PDFs only.

## Resource limits

Each conversion runs in a separate process inside the MarkItDown container, so a malformed or oversized file can't take the service down.

| Variable | Default | Purpose |
| --- | --- | --- |
| `MARKITDOWN_CONVERT_TIMEOUT` | `60` | Seconds before the MarkItDown service stops a conversion. `0` turns the timeout off. PullMD waits 30 seconds for the service to respond, so a conversion that takes longer returns `502`. |
| `MARKITDOWN_MEM_LIMIT` | `1g` | Memory limit for the whole container. |
| `MARKITDOWN_MEM_LIMIT_MB` | `0` | Memory cap per conversion in MB. `0` relies on the container limit. |

Documents fetched by URL are also limited by `PULLMD_MAX_FETCH_BYTES` (default 50 MB).

## Without MarkItDown

If you remove the `markitdown` service and remove the `MARKITDOWN_URL` line from the `pullmd` service, document links and uploads in the formats MarkItDown handles return `502`, and YouTube transcripts are off. Web pages and the [upload formats PullMD reads itself](#upload-formats-pullmd-reads-itself) are unaffected.
