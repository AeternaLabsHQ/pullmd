# Authentication

PullMD is open by default: anyone who can reach it can use it. Before you expose it beyond your own network, turn on sign-in. Set `PULLMD_AUTH_MODE` to one of these values:

| `PULLMD_AUTH_MODE` | Who can use it |
| --- | --- |
| `disabled` (default) | Anyone. No accounts. |
| `single-admin` | One account, created from environment variables. `/signup` is closed. For personal use. |
| `multi-user` | Anyone can sign up at `/signup` (unless you close it). Each user sees only their own history. |

## Turn on sign-in

<Steps>
  <Step title="Set the mode and the first admin">
    ```bash
    PULLMD_AUTH_MODE=single-admin
    PULLMD_ADMIN_EMAIL=you@example.com
    PULLMD_ADMIN_PASSWORD=<admin-password>
    ```

    The admin is created on the first start in this mode. Conversions already in the cache are assigned to the admin.
  </Step>
  <Step title="Restart">
    ```bash
    docker compose up -d
    ```

    If the email or password is missing on the first start, PullMD exits with this message in the log:

    ```text
    ERROR: PULLMD_AUTH_MODE=single-admin requires bootstrap credentials.
    ```
  </Step>
  <Step title="Sign in">
    Open `/login`. Sessions last 90 days and are extended while you use PullMD.
  </Step>
</Steps>

After the admin exists, changing `PULLMD_ADMIN_PASSWORD` does nothing. Use the [admin commands](#admin-commands) to reset it.

## API keys

To authenticate scripts and agents, create an API key:

1. Sign in and open `/settings`.
2. Create a key and copy it. PullMD shows it once.
3. Send it as a bearer token with every request. Replace `<api-key>` with your key:

   ```bash
   curl "https://pullmd.example.com/api?url=https://example.com" \
     -H "Authorization: Bearer <api-key>"
   ```

To create a key from a script, sign in with a form post, keep the session cookie, and post to `/api/keys`:

```bash
curl -s -c cookies.txt -X POST https://pullmd.example.com/login \
  -d "email=you@example.com" -d "password=<admin-password>"

curl -s -b cookies.txt -X POST https://pullmd.example.com/api/keys \
  -H "Accept: application/json" -d "label=ci"
```

The login returns `302` with a `pullmd_session` cookie, or `401` for a wrong email or password. With `Accept: application/json`, `/api/keys` returns `{"key":"pmd_..."}`, and `label` is optional. Without that header, it redirects to `/settings`. A post to `/login`, `/logout`, `/signup`, `/oauth/consent`, `/settings/apps/:clientId/revoke`, `/api/keys` or `/api/keys/:id/revoke` whose `Origin` header (or, without one, `Referer`) names another host gets `403`. A script that sends neither header, like the `curl` calls above, is accepted.

Keys look like `pmd_` followed by 32 letters and digits. PullMD stores only a hash. To revoke a key, open `/settings`.

claude.ai and Claude Desktop sign in with [OAuth](/agents/claude-ai-connector), because they can't send a header.

## Connected apps

`/settings` lists under **Connected apps** every OAuth client that holds a valid refresh token for your account, with when you connected it and when it last refreshed its token. **Revoke** ends that client's refresh tokens, so it can't get a new access token and has to be connected again. An access token it already holds stays valid until it expires, within 1 hour.

## What needs sign-in

| Needs sign-in | Always open |
| --- | --- |
| `/api`, `/api/stream`, `POST /api/html`, `POST /api/file` | `/`, `/help`, static files, `/pullmd.zip` |
| `/mcp` | `/login`, `/signup` |
| `/api/history`, `/api/archive` | Share links, `/s/:id`, hosted figures, `/img/:file` |
| `DELETE /api/cache/:id`, `DELETE /api/cache` | `/api/status`, `/api/recipes/status` |
| `/api/me`, `/settings`, `POST /settings/apps/:clientId/revoke`, `/share` | `/api/stats`, `/api/storage` (short answer, see below), `/api/config` |
| `POST /api/keys`, `POST /api/keys/:id/revoke` | OAuth endpoints, `/web-reader.zip`, `/sw.js` |

Share links and [hosted figures](/guides/documents#hosted-figures) are always open, so anyone with a link can read the shared content. `/api/stats` and `/api/storage` answer everyone with `200`. The counts, sizes and per-domain lists go to the admin, or to everyone when sign-in is off and public history is on; any other caller, a signed-in user who isn't the admin included, gets just `window` or `retentionDays`. `/api/me` answers `401` when you're not signed in, and doesn't exist (`404`) while sign-in is off.

A request to `/api*` or `/mcp` without valid credentials gets `401` with `{"error": "Authentication required"}`. When `PUBLIC_URL` is set, the response carries a `WWW-Authenticate` header whose `resource_metadata` points to `/.well-known/oauth-protected-resource`, which exists only when OAuth is enabled. A browser request to a page such as `/settings` gets a `302` redirect to `/login`.

## Multi-user mode

To let several people sign in, set the mode and the first admin:

```bash
PULLMD_AUTH_MODE=multi-user
PULLMD_ADMIN_EMAIL=you@example.com
PULLMD_ADMIN_PASSWORD=<admin-password>
```

- Each user's history, archive and MCP `list_recent` show only their own conversions.
- The cache itself is shared: if two users convert the same URL, they get the same cached copy and share id. Only the user whose request created the copy sees it in their history, archive and `list_recent`.
- A user's delete removes the entry from their history only. The admin's delete removes the shared copy for everyone. A user's own [stored upload](/guides/documents#keep-an-upload) is the exception: their delete removes it for everyone.

### Close signup

To stop strangers from registering on a public instance, set:

```bash
PULLMD_ALLOW_SIGNUP=false
```

`/signup` then returns `404` and the login page drops its "create an account" link. Create accounts with the [admin commands](#admin-commands).

<Note title="Compose files omit this setting">As of v3.19.0, the compose files don't pass `PULLMD_ALLOW_SIGNUP` to the container. Add `- PULLMD_ALLOW_SIGNUP=${PULLMD_ALLOW_SIGNUP:-}` to the `pullmd` service's `environment:` list. See [Installation](/self-hosting/installation#configure).</Note>

## Admin commands

Run these inside the container as the `app` user (`-u app`), which owns the database. Started as root, the script switches to that user itself. They read the password from standard input, so the command needs an interactive terminal (`docker compose exec`) or a pipe.

| Command | Action |
| --- | --- |
| `node scripts/admin.js list-users` | List accounts |
| `node scripts/admin.js create-user <email>` | Create an account |
| `node scripts/admin.js reset-password <email>` | Set a new password |
| `node scripts/admin.js make-admin <email>` | Make an account an admin |

To reset a password from a terminal:

```bash
docker compose exec -u app pullmd node scripts/admin.js reset-password you@example.com
```

To run a command from a script, pipe the password in:

```bash
echo "new-password" | docker exec -i -u app pullmd node scripts/admin.js create-user someone@example.com
```

Without `-i`, the command prints a usage hint and exits with code 2. Passwords need at least 8 characters, `create-user` makes a non-admin account, and `reset-password` also ends that user's sessions and revokes the refresh tokens of their [connected apps](#connected-apps). API keys stay. Emails need a dotted domain. The 8-character minimum also applies to signup, but PullMD doesn't check the first admin's `PULLMD_ADMIN_PASSWORD`.

## Rate limits

Login allows 10 attempts a minute and signup 5 an hour, per client address. Over the limit, PullMD answers `429` with a `Retry-After` header. Behind a reverse proxy, set [`PULLMD_TRUST_PROXY`](/self-hosting/reverse-proxy) or all visitors share these limits.

## Legacy token

`PULLMD_AUTH_TOKEN` is a single shared bearer token from v1. It works only in `single-admin` mode, maps to the admin, and will be removed in a future major release. PullMD compares it with the environment variable and doesn't store it, so it isn't listed among the API keys on `/settings` and stops working once you remove the variable. Use API keys. Setting it while auth is `disabled` does nothing, and `/api/config` reports `authMisconfigured: true`.
