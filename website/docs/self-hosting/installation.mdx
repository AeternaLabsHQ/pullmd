# Installation

PullMD runs as four containers: the PullMD server and three optional helpers ("sidecars"). The default compose file starts all four with working settings.

| Container | Image | Purpose | Without it |
| --- | --- | --- | --- |
| `pullmd` | `aeternalabshq/pullmd` | API, web app, MCP server, cache | Required |
| `trafilatura` | `aeternalabshq/pullmd-trafilatura` | Second HTML extractor | Readability is the only extractor |
| `playwright` | `aeternalabshq/pullmd-playwright` | Headless browser for JavaScript-heavy pages (about 3.7 GB) | JavaScript-heavy pages may come back thin |
| `markitdown` | `aeternalabshq/pullmd-markitdown` | Documents, and YouTube transcripts when `MARKITDOWN_YOUTUBE=true` is set on `pullmd` | Document links, and uploads in the formats MarkItDown handles, return `502`; no YouTube transcripts. [Upload formats PullMD reads itself](/guides/documents#upload-formats-pullmd-reads-itself) keep working. |

Images are published for `amd64` and `arm64` on Docker Hub, and mirrored on GitHub's registry as `ghcr.io/aeternalabshq/pullmd`, `pullmd-trafilatura`, `pullmd-playwright` and `pullmd-markitdown`.

## Install

To install PullMD, download the compose file and start it:

```bash
mkdir pullmd && cd pullmd
curl -O https://raw.githubusercontent.com/AeternaLabsHQ/pullmd/main/docker-compose.yml
docker compose up -d
```

PullMD listens on `http://localhost:3000`. The cache, history and user accounts are stored in `./data`.

## Configure

All settings are environment variables. Put them in a `.env` file next to `docker-compose.yml` and run `docker compose up -d` again to apply them. A local install needs no `.env`. This example sets the port and the public URL:

```bash
# .env
PORT=3080
PUBLIC_URL=https://pullmd.example.com
```

The compose file passes each variable to the container through its own line.

<Warning title="Seven settings need an extra line">
  `PULLMD_ALLOWED_HOSTS`, `PULLMD_ALLOW_SIGNUP`, `PULLMD_ARTICLE_SERIES`, `PULLMD_COVERAGE_GUARD`, `PULLMD_EMBEDDED_IMAGES`, `PULLMD_EMBEDDED_IMAGES_MAX` and `PULLMD_FILENAME_DATE_PREFIX` are not in the compose file's list as of v3.19.0, so setting them in `.env` alone has no effect. Add the ones you use to the `environment:` list of the `pullmd` service:

  ```yaml
  services:
    pullmd:
      environment:
        - PULLMD_ALLOWED_HOSTS=${PULLMD_ALLOWED_HOSTS:-}
        - PULLMD_ALLOW_SIGNUP=${PULLMD_ALLOW_SIGNUP:-}
  ```
</Warning>

Every variable is listed in the [configuration reference](/reference/configuration).

## Set the public URL

`PUBLIC_URL` is the address people and agents use to reach PullMD. It's written into the `/help` page, the [Claude Code skill](/agents/claude-code-skill) bundle and share links in MCP results, and it's required for [OAuth](/agents/claude-ai-connector).

The default compose file sets it to `http://localhost:${PORT}`. Change it as soon as PullMD is reachable from anywhere else:

```bash
PUBLIC_URL=https://pullmd.example.com
```

## Remove a sidecar

To save disk space or memory, delete the sidecar's block from `docker-compose.yml` and remove its `…_URL` line and its entry under `depends_on` from the `pullmd` service. PullMD notices the missing URL and skips that step.

The Playwright sidecar saves the most space: it adds about 3.7 GB of browser binaries. Without it, PullMD returns what static extraction found and says so in `extractor_reason`.

## Pin a version

`:latest` follows the newest release. To upgrade only when you choose, pin a version on all four images, for example:

```yaml
image: aeternalabshq/pullmd:3.19.1
```

`aeternalabshq/pullmd:2` stays on the last 2.x release. See [Upgrading](/self-hosting/upgrading).

The downloaded compose file uses `:latest` on every image. To pin all four to one version, replace the tag:

```bash
sed -i.bak 's/:latest/:3.19.0/' docker-compose.yml
```

## Run a second instance

The compose file sets a fixed `container_name` on each service (`pullmd`, `pullmd-trafilatura`, `pullmd-playwright` and `pullmd-markitdown`), so a second copy fails with a name conflict. To run another instance, delete those lines, give the stack a project name with `-p`, and set a different `PORT` in its `.env`:

```bash
mkdir pullmd-2 && cd pullmd-2
curl -O https://raw.githubusercontent.com/AeternaLabsHQ/pullmd/main/docker-compose.yml
sed -i.bak '/container_name:/d' docker-compose.yml
echo 'PORT=3081' > .env
docker compose -p pullmd-2 up -d
```

Compose names the containers after the project (`pullmd-2-pullmd-1`, `pullmd-2-trafilatura-1`, and so on) and gives the stack its own network, so the sidecars of the two instances stay separate. The second instance listens on `http://localhost:3081`, keeps its cache in its own `./data`, and takes its `PUBLIC_URL` from `PORT` unless you set it. To stop it, run `docker compose -p pullmd-2 down` in that folder.

## Run the image without Compose

To start the server image with `docker run`, set `CACHE_DB` and mount a folder for it. Without `CACHE_DB`, the container exits at start with `TypeError: Cannot open database because the directory does not exist`. The compose file sets `CACHE_DB=/data/cache.db` for you.

```bash
docker run -d --name pullmd -p 3000:3000 \
  -e CACHE_DB=/data/cache.db \
  -v "$PWD/data:/data" \
  aeternalabshq/pullmd:3.19.0
```

The server listens on port `3000` inside the container. Without the sidecars, `GET /api/status` reports each one as `not-configured`, and Readability is the only HTML extractor. To use sidecar containers, set `TRAFILATURA_URL`, `PLAYWRIGHT_URL` and `MARKITDOWN_URL`, as in the compose file. To turn on sign-in, add `-e PULLMD_AUTH_MODE=single-admin -e PULLMD_ADMIN_EMAIL=<email> -e PULLMD_ADMIN_PASSWORD=<password>`, as described in [Authentication](/self-hosting/authentication).

## Run without Docker

To develop PullMD, run the server with Node.js 22 (the version the Docker image uses). Without the sidecars, Readability is the only HTML extractor, and document links and uploads in the formats MarkItDown handles return `502`.

```bash
git clone https://github.com/AeternaLabsHQ/pullmd.git
cd pullmd
npm install
npm start      # http://localhost:3000
npm test       # node --test
```

The cache is created at `./data/cache.db`. Set `TRAFILATURA_URL`, `PLAYWRIGHT_URL` and `MARKITDOWN_URL` to use sidecar containers you run separately. Here `PORT` sets the port the server listens on.

`npm start` and the Docker image start the server with `--max-http-header-size=65536`, because YouTube's response headers can exceed Node's 16 KB default. If you run `node server.js` directly, add that flag, or YouTube URLs fail with `fetch failed`.
